# 쇠타임 — 설계 문서

## 1. 제품 성격

혼자 쓰는 개인용 운동 PWA. 광고 없이 **세트 간 휴식 타이머**에 집중한다.
서버 없이 브라우저 안에서만 동작하며 GitHub Pages로 정적 배포한다.

접근성(a11y), 테스트 커버리지, 린터, 다중 사용자 대응은 범위 밖에 둔다.

## 2. 기술 결정

| 항목 | 결정 |
| --- | --- |
| 스택 | Vite + React + TypeScript + Tailwind (local-ledger와 동일) |
| 배포 | GitHub Pages, `base: '/soetime/'`, main 푸시 시 자동 |
| 저장소 | **localStorage** (IndexedDB 아님 — 3.3 참고) |
| 알림음 | Web Audio로 생성 (오디오 파일 없음 → 오프라인에서도 확실히 울림) |

## 3. 핵심 설계

### 3.1 타이머는 시간을 세지 않는다

`setInterval`로 흘러간 시간을 누적하는 방식은 **반드시 틀어진다.**
탭이 백그라운드로 가면 타이머가 조절되거나 멈추고, PWA는 통째로 정지될 수 있다.
헬스장에서 쉬는 동안 사용자는 반드시 화면을 잠그거나 다른 앱을 쓴다.

그래서 **끝나는 시각(`endsAt`, 에폭 ms)만 기억하고** 매 렌더에서 `Date.now()`와 비교해
남은 시간을 계산한다. 몇 분간 얼어 있었어도 돌아오는 즉시 정확한 값이 나온다.
`setInterval`은 화면을 다시 그리기 위한 신호일 뿐 시간의 근거가 아니다.

`endsAt`은 localStorage에도 저장해, 앱이 종료됐다 다시 열려도 타이머가 이어진다.

### 3.2 Wake Lock은 매번 다시 잡아야 한다

브라우저는 문서가 가려지면(앱 전환, 화면 잠금) wake lock을 **자동 해제하고 복구해주지 않는다.**
`visibilitychange`에서 재획득하지 않으면 한 번 가려진 뒤로 영영 화면이 꺼진다.
이것이 wake lock 타이머의 대표적인 버그다.

제약:

- **iOS 홈 화면 웹앱은 iOS 18.4부터 동작한다.** 그 이전에는 요청이 실패한다
- 실패해도 앱은 계속 동작하고, 화면이 꺼질 수 있다는 안내만 띄운다

### 3.3 저장소는 localStorage로 충분하다

세트 1건 ≈ 50자, 한 세션(5종목×4세트) ≈ 1.2KB, 주 4회면 연 240KB.
10년을 써도 2.4MB로 5MB 안쪽이다.

IndexedDB는 비동기·버전관리·마이그레이션이 따라붙는데 이 규모에서는 과하다.
필요해지면 그때 옮긴다.

### 3.4 백그라운드 알림은 만들지 않는다

화면을 잠근 상태에서 "휴식 끝"을 알리는 것은 정적 PWA로는 불가능하다.
Push API는 서버(VAPID + 푸시 서비스)가 필요하고, 정지된 페이지에서는 코드가 돌지 않는다.

서버 없이 알림을 예약하는 **Notification Triggers API**(`TimestampTrigger`)를 검토했으나
구글이 개발을 중단했다 — "The development of Notification Triggers API has ended."
문서상 "No longer pursuing"으로 분류되어 있고, 지금은 `about://flags`의 실험 기능을
켜야만 동작한다. 제품에 쓸 수 없다.

그래서 **화면을 켜두고 쓰는 타이머**로 정한다. 이것이 이 앱의 사용 전제다.

**알림은 보고 있는 동안 끝났을 때만 울린다.**
자리를 비운 사이 이미 끝났다면 몇 분 늦은 알림은 정보가 아니라 소음이라 조용히 넘어간다.
구현은 완료를 감지한 시점이 `endsAt`으로부터 2초 이내이고 문서가 visible일 때만 알린다.

"N분 전에 끝남" 같은 경과 시간 표시는 넣지 않는다. 휴식이 끝난 사실은 본인이 알고,
몇 분 지났는지는 운동에 영향을 주지 않는다. 앱이 재시작된 경우에는 만료된 타이머를
버리고 초기 화면으로 시작한다.

`navigator.vibrate`는 **iOS에서 미지원**이므로 설정에서 비활성 처리한다.
안드로이드에서는 정상 동작하지만, 화면이 꺼진 상태에서는 소리와 마찬가지로 울리지 않는다
(브라우저가 숨겨진 페이지의 진동 호출을 무시한다).

### 3.5 루틴 진행 모드

상단 탭으로 **타이머 / 루틴**을 나눈다. 루틴은 등·어깨·가슴·하체 4개를 기본으로 두고
운동 목록을 편집할 수 있다 (첫 실행에 빈 화면을 주지 않도록 기본 운동을 채워둔다).

**진행 단위는 세트다.** 운동마다 세트 수와 휴식 시간을 따로 가진다
(데드리프트 3분, 사이드 레터럴 45초처럼 종목별로 크게 다르기 때문).

```
[세트 완료] 탭 → 진행을 먼저 옮기고 → 다음 세트의 휴식 시작
마지막 세트면 다음 운동으로, 마지막 운동의 마지막 세트면 휴식 없이 완료
운동이 바뀔 때는 새 운동의 휴식 시간을 쓴다
```

진행 상태(`SOETIME_PROGRESS_V1`)는 localStorage에 저장해 **앱이 죽어도 이어서 한다.**
헬스장에서 화면이 꺼져 PWA가 정리되는 일이 잦다.

**무게·횟수는 기록하지 않는다.** 완료 후에도 요약을 띄우지 않는다.
이 모드의 목적은 "다음에 뭘 할지 잊지 않고 넘어가는 것"이지 운동 일지가 아니다.

### 3.6 백업은 앱 바깥의 사고를 막는 유일한 수단이다

앱 안에서 실수로 루틴을 지우는 것은 되돌릴 수 있지만,
**PWA 삭제나 브라우저 사이트 데이터 비우기는 앱이 개입할 여지가 없다.**
파일로 빼둔 JSON 하나가 유일한 복구 경로다.

local-ledger에서 쓰던 순서를 그대로 옮겼다.

1. **검증** — `routines` 배열이 없으면 거부한다.
   이 검사가 없으면 아무 JSON 객체나 통과해 루틴을 빈 상태로 덮어쓴다
   (local-ledger에서 실제로 `{"name":"package"}`가 87건을 0건으로 만들었다)
2. **확인** — 가져올 내용과 현재 내용을 나란히 보여주고 `confirm`을 받는다
3. **스냅샷** — 덮어쓰기 직전 상태를 `SOETIME_PREIMPORT_V1`에 한 벌 남긴다.
   잘못 가져왔을 때 '되돌리기'가 쓰는 값이다
4. **저장 실패를 삼키지 않는다** — `saveRoutines`/`saveSettings`가 boolean을 돌려주고,
   실패하면 "복원됐다"고 말하지 않는다

검증 로직은 `sanitizeRoutines`/`sanitizeSettings` 한 곳에만 둔다.
저장소에서 읽을 때와 백업에서 읽을 때가 다른 규칙을 쓰면
한쪽에서만 통과하는 데이터가 생긴다.

**백업에 담지 않는 것:** 진행 중인 타이머(`SOETIME_RUNNING_V1`)와
루틴 진행 상황(`SOETIME_PROGRESS_V1`). 둘 다 지금 이 순간에만 의미가 있는 값이라
나중에 복원하면 오히려 엉뚱한 상태가 된다.

**복원하면 진행 중이던 루틴을 접는다.** 루틴 id가 통째로 바뀌어
진행 상황이 가리킬 곳이 없어지기 때문이다.

### 3.7 저장 실패는 화면에 드러낸다

`localStorage.setItem`은 용량 초과나 시크릿 모드에서 실제로 예외를 던진다.
이걸 `catch`로 삼키면 **앱은 정상처럼 보이는데 아무것도 남지 않는다.**
루틴을 20분 손보고 앱을 닫았더니 그대로인 상황이 여기서 나온다.

`saveSettings`/`saveRoutines`가 boolean을 돌려주고,
하나라도 실패하면 헤더에 닫을 수 없는 빨간 배너를 띄운다.

배너의 탈출구는 백업 내보내기다. 중요한 건
**`BackupSection`이 localStorage가 아니라 React state를 내보낸다**는 점이다.
저장에 실패한 그 편집 내용이 그대로 파일에 담겨야 탈출구로서 의미가 있다.

저장 effect에서 두 함수를 `&&`로 묶지 않는다.
묶으면 설정 저장이 실패했을 때 루틴은 저장 시도조차 되지 않는다.

## 4. 로드맵

1. **휴식 타이머** — 완료. 프리셋, ±15초, 화면 켜둠, 소리·진동, 앱 재시작 시 복구
2. **루틴 진행 모드** — 완료. 3.5 참고
3. **지난 기록 표시** — 보류. 무게·횟수를 기록하기 시작하면 성격이 달라진다.
   실제로 써보고 필요해지면 그때 판단한다
4. **백업 내보내기/복원** — 완료. 3.6 참고

## 5. 하지 않을 것

- **광고, 계정, 서버.** 이 앱의 존재 이유가 그것들이 없다는 것이다
- **AI 운동 추천.** 부상 위험이 있는 영역이고, 검증할 방법이 없다
